# Dream-RSI v2 第三章复现：缺口与实施方案

日期：2026-10-12。当前状态：源码静态审查完成；本次仅新增实施说明，没有修改算法或执行测试。

以上状态与缺口描述是实施前的审查快照。实现与验收进展另见 [V2_ACCEPTANCE.md](V2_ACCEPTANCE.md)。

## 1. 基准与结论

- 基准论文：Dream-RSI，arXiv:2609.14858v2，2026-10-06。
- 本地原文：[dream-rsi-2609.14858v2.pdf](../reference/papers/dream-rsi-2609.14858v2.pdf)。
- 原文第三章：https://arxiv.org/html/2609.14858v2#S3 。
- 下载文件 SHA256：`9d632678c6c71da926ce2276e3c9d31697a5397d368bbdc4f221bd966d2e3476`。
- 范围：第三章的方法、数据流及在线/回放一致性。用户自行设计场景实验，第四章的数据集、基准、效果和超参数不属于本次复现要求。

**当前不能判定为完整复现。** 两项明确的方法缺口是父分支观察继承与完整历史上下文访问。另有策略状态一致性风险、记录与快照持久化问题，以及有限轮次的末轮更新边界。

以下核心机制在静态审查中已经对齐 v2，不应重写为 v1 的方法：root + leaves 的动作集合、批次并行与批次结束后决策、历史树回放、固定五点 rho 网格、归一化超体积减并行惩罚、跨历史世界平均、M 个版本含 incumbent、M−1 次顺序修订，以及包含 incumbent 的最优选择。此前针对目标公式与 rho 扫描的否定结论已撤回。

“代码已有”与“所有运行边界通过验收”应分开记录；下文的方案要求补充后者。

## 2. 缺口、证据与影响

### G1 — 父分支的累积观察未传给续写代理（必须补齐）

第三章 Discovery trees 段要求从父节点保存的工作区继续，并继承该父分支的累积观察；节点保留自身之前的生成历史。

证据：

- `src/dream_rsi/adapters/base.py` 的 `DiscoveryBackend.generate` 只有任务、父工作区、跨世界摘要等参数，没有父分支观察链。
- `src/dream_rsi/adapters/pi.py:91` 复制父工作区，`:101` 构造任务与世界摘要提示。
- `src/dream_rsi/adapters/_pi_worker.py:197` 使用 `--no-session` 开启新会话。
- `src/dream_rsi/runtime/online.py:282` 取得评测结果，随后只将分数、状态、摘要和摘要值记录到节点，没有将评测 detail 交给下一次续写。

因此代理继承了文件，却未获得框架提供的父节点分数、评测诊断及累积生成观察。代理自行留下笔记不能替代框架保证。

新会话本身不是违背论文；完整重建上下文可以满足要求，无需强制恢复 Pi 原生会话。

### G2 — 已完成历史只剩最近五个世界的统计摘要（必须补齐）

第三章 Online rollout 段要求新一轮发现可访问已完成历史 H_(t−1)，同时与当前构建的树分开。

证据：

- `src/dream_rsi/runtime/controller.py:761` 的 `_history_entries` 只生成节点数、最高分、策略 ID 与 `sealed ...` 等元数据。
- `src/dream_rsi/adapters/dsh.py:97` 的共享提示构造函数使用 `history[-5:]`；Pi 同样调用该函数。

目前既不能从这个提示检索具体尝试及观察，也无法访问被截掉的早期世界。删除 `[-5:]` 只是第一步，仍需提供历史内容。

### G3 — 在线与回放对策略内部状态的处理不同（条件性正确性风险）

第三章 Shared decision interface 段要求两阶段共享决策接口，区别在动作后的状态转移。

证据：

- `runtime/controller.py:510` 的在线选择每个批次新建并关闭策略进程。
- `runtime/controller.py:1052` 的回放每个世界开启一个进程，`:1058` 将同一 `session.select` 用于五个 rho 及各轮决策。
- `policy/_policy_worker.py` 一次加载模块后循环处理请求。
- `runtime/policy_development.py` 要求纯函数，但静态检查未排除模块全局计数器、可变容器等内部状态。

纯函数策略不受这一差异影响。带状态的被接纳策略则可能在 rho 之间串扰，并让离线分数不代表在线行为。不能据此断言现有每个策略的分数都错了。

### G4 — 历史记录不足以重建完整观察与工作区（记录与工程缺口）

证据：

- `runtime/online.py:304` 的 `observation_digest` 指向候选入口文件，而非完整的生成/评测观察记录。
- `adapters/pi.py:142` 的 `raw_response_digest` 是最终文本的哈希，不是该文本已进入 CAS 的证明。
- Pi 已有运行诊断事件日志，但日志有截断，且没有作为节点观察链传给后续代理。
- `storage/cas.py:116` 的目录遍历仅计算文件哈希；`:217` 的 `put_tree` 保存清单，不保存清单里全部文件的内容，也没有目录恢复接口。

原工作区目录仍可供当前在线流程复制，因此“CAS 只有清单”不等于每次在线续写已经失败。但删除、移动或改写这些目录后，不能仅凭所记 snapshot digest 恢复整个工作区；原始评测 detail 和生成历史也不能仅凭节点中的几个哈希完整重建。

本项应与 G1 合并建设数据基础。论文没有规定必须用 CAS；选择 CAS 是本项目完成保存/恢复承诺的一种实现。

### G5 — 最后一轮发现之后没有执行离线改进（有限轮次边界差异）

第三章 Online rollout 段的顺序是生成 T_t、加入 H_t、再进入离线评估。

`runtime/controller.py:369` 的循环在下一轮开头评估此前世界，`:489` 附近在最后一次封存后结束。因此 N 个在线世界通常对应 N−1 次离线选择。

中间轮的“下一轮开始前选择”与论文的更新顺序可以等价，不能将整个循环判为错误；差异集中在运行终点。若声称完成 N 次“在线 + 离线”迭代，应补最后一次选择，并保存供下一次部署的策略。预算中断、无可评分历史等情况要单独报告。

### G6 — 策略改进反馈缺少可读的逐步观察（建议与上述记录一起补）

`runtime/controller.py:1119` 的 `_feedback` 已提供分数、动作批次、揭示顺序与停止原因，但节点轨迹主要是 ID，没有逐步节点分数、诊断或生成说明。

论文要求利用轨迹、分数和此前反馈修订。现有实现并非完全没有轨迹；补充可读观察能让策略开发代理理解动作与结果的关系。第三章没有强制特定 JSON 字段或完整聊天文本进入 policy 输入，不能把任意字段扩充都称为论文硬性要求。

## 3. 实施方案与顺序

### 阶段 A：建立观察记录，再接通发现上下文（G1、G2、G4）

1. 定义版本化、不可变的 `AttemptObservation`：world/node/parent 标识、实际评测分数与状态、对代理公开的评测诊断、生成说明、生成记录与完整工作区的内容引用。根节点使用明确的初始观察，score=0。
2. 定义 `ContinuationContext`：从根到所选父节点的累积观察链，以及已完成世界历史索引。由控制器构建，禁止代理自己填写评测分数。
3. 对所有节点保存原始评测结果及有效生成记录，包括实际请求、接口公开的消息和工具结果。用于排查故障的有界事件日志与用于继承的正式历史分开；不能用截断后的日志或 500 字摘要声称完整保存。这里不要求取得模型接口未公开的内部推理。公开诊断与评测私有内容分开；秘密测试数据、凭据和固定 evaluator 源码不进入代理上下文。正常、异常、超时节点使用同一记录流程。
4. 完成内容快照：目录清单引用的文件都进入 CAS，提供校验与恢复接口。定义空目录、内部链接和特殊文件行为，维持现有 Windows 路径/链接防逃逸约束。恢复到明确的目标目录，损坏或缺失内容必须报错。
5. 扩展 `DiscoveryBackend.generate`；Pi、DSH 和 fixture 后端同步接入。提示明确父节点观察及历史资料所在位置；继续使用新会话时，保证数据完整可读。
6. 为全部 H_(t−1) 建立只读历史资料目录/索引，包含树结构、已完成节点的观察与候选内容。大历史用索引与按需读取处理，避免把所有文本硬塞进单个提示。取消固定最近五个世界截断；摘要可以保留，但不能成为唯一资料。
7. 当前树与已完成历史分开。只给当前尝试提供所选父分支和已完成历史，明确不暴露尚未产生的结果。每次记录实际传入上下文的内容哈希。

主要文件：`adapters/base.py`、`adapters/pi.py`、`adapters/dsh.py`、`adapters/_pi_session.py`、`runtime/online.py`、`runtime/controller.py`、`domain/models.py`、`storage/cas.py`、`storage/sqlite_registry.py` 及协议序列化相关位置。实际改动前读取全部调用点。

验收：

- 构造“只有看到父评测诊断才能修复”的 fixture；确认续写请求收到正确观察。
- 两条分支的累积观察不同，不能混入另一分支的未继承观察。
- 在至少六个已完成世界后，最早世界的具体尝试仍可检索；当前未完成世界不混入 H_(t−1)。
- 在临时测试目录移除或修改原工作区后，仍能从快照恢复所有纳入快照的内容；缺失/篡改 blob 被拒绝。
- timeout/error 的观察也被保存；旧记录缺资料时明确标为旧格式/不完整，禁止凭摘要伪造历史。

### 阶段 B：统一决策语义并完善离线反馈（G3、G5、G6）

1. 保留项目现有纯函数 `select(observation, rho)` 契约。推荐在线与回放均每次决策使用全新模块状态，通过共用封装调用隔离策略 runner。不要只在每个 rho 重置，因为那仍与在线每次决策重置不同。进程启动成本如需优化，先实现等价的可靠重置，再证明行为一致。
2. 补全回放逐步记录：当时的可见 observation、选择批次、揭示的节点及其公开结果、终止原因。两阶段从同一公开观察构造逻辑获取节点信息。
3. Policy 可以只看到已揭示前缀；不能把完整世界、隐藏子节点数、B/S 或通向完整世界的文件路径塞进决策输入。更多观察字段是本项目的接口设计，不是论文指定字段。
4. `_feedback` 给策略开发代理提供上个刚评估版本的逐步可读轨迹和分数，并继续累积此前修订反馈。允许开发代理看到各世界总评分资料，不等于允许回放中的 policy 看到隐藏世界。
5. 对正常完整迭代补最后一次离线选择，保存最终选中策略；当前最后一个世界由什么策略生成与最终输出策略分别记录。调整 resume 与 selection ID，保证恢复不会重复修订或再次计费。
6. 不可评分世界和预算截断保留真实状态，不为补齐选择次数合成正分、虚构候选或额外在线尝试。

主要文件：`runtime/controller.py`、`runtime/replay.py`、`policy/runner.py`、`policy/_policy_worker.py`、`policy/protocol.py`、`domain/tree.py`、策略开发和回放持久化相关位置。

验收：

- 用带模块计数器的策略证明在线与回放对相同 observation/rho 输出一致，调换 rho 评估顺序不影响各 rho 结果。
- 已揭示节点的公开观察在线与回放一致；决策输入不包含隐藏未来信息。
- 每次修订收到刚评估版本的轨迹与分数；M 个版本、M−1 次修订语义保持不变。
- 正常完成 N 个可评分世界时有 N 次离线选择；恢复运行不会重复选择。特殊终点有明确原因。
- 使用会在被调用时失败的 agent/evaluator 替身，证明回放确实不调用两者，而不只检查结果中的零计数。

### 阶段 C：补充第三章完成证据

1. 补充上面各项的自动化回归与小规模集成测试；保留独立 Eq.(1) oracle 比较、动作合法性、root 最早未观察子节点、非 root 唯一 continuation、并行屏障及非空无进展轮次测试。
2. 更新 `tools/verify_run.py`：检查内容引用可解析、父观察链一致、历史访问范围、逐步回放记录、选择次数及版本来源；不能把旧的摘要格式自动标成完整 v2 复现。
3. 更新 `docs/ALGORITHM.md`、`docs/VALIDATION.md` 及使用说明，引用固定 v2，准确报告新增证据与未验证适配器。
4. 保存一份可复查的小规模验收报告，列出配置、源码版本、数据/快照引用、测试结果和剩余限制。
5. 本地测试通过后，再按明确的模型调用预算做 Pi 实际运行验收。真实调用证据与 fixture 证据分开；DSH 是否另做 live 验收不阻塞用户的 Pi 场景。

完成判据：G1/G2 的上下文完整可访问、G3 的在线回放一致性得到保证、G4 的历史可恢复、G5 的结束语义准确实现并说明，且上述证据可独立复查。G6 完成反馈改进。该结论只代表第三章机制完成，不代表用户场景中的有效性或论文第四章效果已复现。

## 4. 数据兼容与交付约束

- 更改 Node/Replay/观察序列化时显式更新格式版本与校验；既有 run 能否只读、迁移或拒绝恢复必须写清楚。
- 改动内容引用会影响 world_digest；旧版本摘要不能静默解释成新版本记录。
- 不改固定发现模型、评测器或评分公式来制造策略提升；任务约束属于用户场景配置。
- 每阶段交付改动清单、回归结果、未完成项；验收报告不能仅写“通过”。
- 本方案没有启动真实模型调用，没有修改算法源码，也没有替用户选择新实验。

## 5. 可直接给 Codex 或 Claude Code 的实现指令

> 在当前仓库实现 `docs/V2_REPRODUCTION_PLAN.md` 的阶段 A、B、C，基准为本地 `reference/papers/dream-rsi-2609.14858v2.pdf` 的第三章。先读取仓库适用说明和全部相关调用点，按 A→B→C 小步修改并执行相应回归测试。优先解决父分支观察继承和完整历史访问，补齐实际内容存储；统一在线与回放的策略状态语义；补最后一轮离线选择、恢复语义及可读回放反馈。现有 v2 Eq.(1)、五点 rho、M 含 incumbent 和动作集合已对齐，不要改回 v1。用户的场景实验独立于第四章，不要求复现第四章数据或成绩。保持固定 evaluator 的私有内容隔离，policy 只能看到已揭示前缀。格式变化显式版本化，禁止为旧记录虚构完整观察。完成后交付源码改动、回归结果和可复查验收报告；真实 Pi 调用在已有明确预算内执行，缺少预算时先完成全部本地工作并说明尚需的调用量。
